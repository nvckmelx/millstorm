# Millstorm — правила проекта для Claude

Браузерная PvP tower defense (1v1 / 2v2 / 3v3), играют с друзьями по ссылке.
Полный дизайн — `docs/design.md`. Текущая задача — `docs/TASK-01-prototype-week1.md`.

## Стек (не менять без обсуждения)
- TypeScript (strict) везде, npm workspaces: `shared/`, `server/`, `client/`.
- `shared/` — чистая логика: правила, симуляция, типы, загрузка `shared/data/*.json`. Без DOM, без Node API. Используется сервером и (позже) ботом/обучением.
- `server/` — Node.js + Colyseus. Сервер авторитетный: симуляция идёт ТОЛЬКО на сервере, 20 тиков/с.
- `client/` — Phaser 3 + Vite. Клиент отправляет только команды (build / upgrade / sell / send / ping) и отрисовывает состояние с интерполяцией.
- Тесты: Vitest для `shared/`.

## Принципы
1. Данные, а не код: все числа баланса и волны — в `shared/data/balance.json` и `waves.json`. Никаких магических чисел в логике.
2. Тропа фиксирована (waypoints из balance.json). Никакого мейзинга и поиска пути. Враг хранит `progress` вдоль ломаной.
3. Сервер валидирует каждую команду: хватает ли ресурса, свободна ли клетка, не тропа ли, открыта ли отправка, не закрыта ли очередь.
4. Детерминированная симуляция в `shared/` с фиксированным шагом `dt = 1 / tickRate`; без `Math.random()` без сида.
5. Маленькие коммиты, после каждой задачи — `npm test` и `npm run build` должны проходить.

## Оригинальность (обязательно)
- Никаких ассетов, названий, текстов, звуков и иконок из Warcraft 3, его кастомных карт или других игр.
- Названия юнитов — только из `docs/design.md` / `balance.json`.
- В прототипе графика — простые фигуры (круги, квадраты, цвета типов брони). Никаких скачанных спрайтов без явной свободной лицензии; каждый внешний ассет записывается в `docs/assets-registry.md` (файл → источник → лицензия).

## Команды (должны работать после недели 1)
- `npm install` — установка
- `npm run dev` — сервер (порт 2567) + клиент (порт 5173) одновременно
- `npm test` — тесты shared
- `npm run build` — сборка всех пакетов
